SLIDE 3 — TECHNICAL ARCHITECTURE
Час: 02:00–04:00 | 2 хвилини
Дія: перша хвилина — компоненти та стан зліва; друга — рух даних і папки справа.
Показуй відповідний блок схеми, а не просто перелічуй назви.

ENGLISH SPEECH:
I built the interface with React and TypeScript.
React lets me divide the shop into reusable components.
TypeScript helps me check data types during development.

On the left, you can see the main component structure.
App brings together the header, pages, cart drawer and footer.
Home displays product cards. Each card receives its product data through props.

Form values and filters use local state.
The cart uses React Context because several components need the same cart data.
I also save the cart in localStorage, so it stays after a page refresh.

On the right, you can see the data flow.
The catalogue loads products from a JSON file.
Checkout sends an order to the server endpoint, called API orders.
The server validates the request and saves the order in Supabase.
After saving it, the server attempts to send a Telegram notification.
A notification failure does not undo the saved order.

I use CSS Modules because separate style files are easier for me to read and edit.
Clerk handles authentication, and Vercel hosts the website and the order API.
The folders separate reusable components, pages, shared state and server code.

ПОВНИЙ ПЕРЕКЛАД УКРАЇНСЬКОЮ:
Я створила інтерфейс за допомогою React і TypeScript.
React дозволяє поділити магазин на компоненти, які можна використовувати повторно.
TypeScript допомагає мені перевіряти типи даних під час розробки.

Ліворуч ви бачите основну структуру компонентів.
App об'єднує шапку сайту, сторінки, панель кошика та підвал.
Home показує картки товарів. Кожна картка отримує дані свого товару через props.

Значення форм і фільтри використовують локальний стан.
Кошик використовує React Context, тому що кільком компонентам потрібні
ті самі дані кошика.
Я також зберігаю кошик у localStorage, тому він залишається після оновлення сторінки.

Праворуч ви бачите рух даних.
Каталог завантажує товари з JSON-файлу.
Сторінка оформлення надсилає замовлення до серверної кінцевої точки API orders.
Сервер перевіряє запит і зберігає замовлення в Supabase.
Після збереження сервер намагається надіслати повідомлення в Telegram.
Помилка повідомлення не скасовує збережене замовлення.

Я використовую CSS Modules, тому що окремі файли стилів мені легше читати й редагувати.
Clerk відповідає за авторизацію, а Vercel розміщує сайт і API замовлень.
Папки відокремлюють компоненти для повторного використання, сторінки,

ENGLISH SPEECH:
One real problem was a checkout failure on the old GitHub Pages address.
The same shop worked on the main Vercel site.

First, I compared the two addresses.
On the main site, I confirmed that the order appeared in Supabase
and that the Telegram notification arrived.
This showed that the order flow worked on Vercel.

With AI assistance, I compared the hosting setups.
GitHub Pages serves static files. It cannot run our server-side order API.
Vercel can host both the frontend and this API.
The old address still opened a shop interface, but it could not process the order.

The solution was to redirect old GitHub Pages links to the main site.
I published the changes and checked the redirect.
Customers now reach the working checkout.

This taught me to check the deployment environment as well as the frontend code.

ПОВНИЙ ПЕРЕКЛАД УКРАЇНСЬКОЮ:
