4. Remaining findings, recommendations and limits

P2 — Dependency maintenance (registry advisory severity: high)
- npm audit --omit=dev exited 1: 2 high entries, 0 critical entries.
- react-router 7.18.0 and react-router-dom 7.18.0 refer to one underlying advisory:
  GHSA-qwww-vcr4-c8h2, RSC-mode CSRF handling.
- The advisory states that unstable RSC APIs are required for applicability. This
  project uses BrowserRouter; no RSC imports, RSC Vite plugin or server RSC handler
  were found. No affected application path was identified; that is a code-review
  assessment, not a general guarantee of security.
- The advisory lists 7.18.2 as a patched 7.x release. A targeted patch update is
  recommended as separate maintenance, followed by tests/build/navigation checks.
- Dependencies were not changed because the owner's prompt prohibits unapproved
  upgrades. No npm audit fix command was run.
- Source: https://github.com/advisories/GHSA-qwww-vcr4-c8h2

P2 — Authentication verification and localisation
- Sign-in/sign-up/profile components exist and their route opens. A real complete
  sign-in/sign-up/sign-out journey has not been independently checked.
- Clerk is in development mode and embedded forms include English text.
- The order flow is guest checkout; no Clerk-linked order history is implemented.

P2 — Accessibility verification
- Manual keyboard/dialog checks were performed. Screen-reader testing and a full
  contrast audit remain open; native datalist/title appearance depends on browser.
- Styling the city popup or replacing the title tooltip was discussed but deferred.

P2 — Reliability and scaling limits
- An unresolved retry marker depends on the same payload and tab sessionStorage.
  Closing the tab or clearing data can lose it; different tabs are not deduplicated
  unless they send the same request ID.
- Telegram delivery has no durable queue or delivery retry. An order can remain
  saved even if a notification fails. Notification fetch has no explicit timeout.
- Rate limiting/abuse protection and a committed automated browser E2E suite are
  not implemented. Existing automated order tests use intercepted network calls.
- The full supplier catalogue is downloaded. The importer appends new IDs but
  does not refresh prices or stock for existing IDs.

Current business scope
- Payments, stock confirmation and fulfilment are manual. There is no payment
  gateway, live postal integration or admin dashboard.
- More manufacturers and German localisation are future ideas.

6. Decisions to understand for the Fachgespraech

- Components and props: Header receives callbacks; ProductCard receives a product.
- Context: one cart state is shared across header, drawer and checkout.
- useState versus useRef: state renders the UI; a ref blocks immediate repeat clicks.
- React keys: a new filter combination remounts ProductResults and resets its batch.
- Browser storage: localStorage persists the cart; sessionStorage retains pending
  request IDs within a tab. Different website origins have separate storage.
- Async requests: show loading/error/success explicitly; do not assume a lost
  response proves that a write failed.
- Server validation: browser values can be edited; verify products/prices and set
  initial statuses on the server. Calculate currency in integer kopiykas.
- Idempotency: one purchase attempt keeps one UUID; the unique primary key also
  handles concurrent inserts. Check matching purchase details before returning a receipt.
- Security: a private server key and RLS/table privileges serve different purposes.
  A VITE_ variable is public configuration, never a place for a server secret.
- Notifications: saving the order and delivering a notification are separate steps.
- Hosting: GitHub stores source, Vercel runs frontend/API, Pages serves a redirect.
  SPA direct routes need a host fallback that does not intercept API requests.
- Performance: mount fewer cards, defer off-screen images, and use a smaller
  lossless encoding. These changes do not reduce the full JSON download.
- Testing: mocks check logic, local PostgreSQL checks constraints, browser checks
  verify UI wiring, and owner evidence confirms the checked production purchase.
- AI assistance: describe the help transparently and take responsibility for code
  review, verification and independent understanding.
